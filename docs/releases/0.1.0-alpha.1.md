# 0.1.0-alpha.1 release notes

> Release candidate. This version has not been published.

## Release-only scope

This candidate proves the post-bootstrap stage-only npm Trusted Publishing path. It does not
change the provider route, model catalog, OAuth behavior, credential persistence, CLI schemas, or
runtime compatibility.

It adds:

- the final secret-free exact-artifact record for `0.1.0-alpha.0`;
- OIDC staging of the one verified workflow artifact for separate maintainer approval;
- fail-closed serialization of manual release runs without in-progress cancellation;
- the post-bootstrap npm `alpha` and `latest` dist-tag policy.

## Verified compatibility

- DeepSeek Harness `0.1.0-rc.7`
- `@deepseek-ai/cordis` `4.0.1`
- `@earendil-works/pi-ai` `0.82.1`
- Node.js `^22.19.0 || ^24.0.0 || ^26.0.0`
- Linux and macOS

## Publication plan

After this metadata reaches protected `main`, one workflow job builds the candidate and all six
supported OS and Node cells verify and install those same bytes. The workflow may then stage that
exact artifact through OIDC, but cannot publish or approve it.

Before approval, the maintainer downloads the staged candidate, compares it with the workflow
artifact, confirms `alpha` will move while `latest` remains on `0.1.0-alpha.0`, and tags the exact
commit. Approval requires two-factor authentication outside GitHub Actions. Registry download,
checksum comparison, packed installation, and a matching GitHub prerelease follow publication.

## Security and evidence

No npm token, OAuth credential, account identifier, authorization data, local path, environment
dump, or model conversation belongs in the workflow artifact or final release record. The final
record will replace this candidate marker with the exact commit, SHA-256, publication date,
dist-tags, and secret-free pass/fail evidence.
