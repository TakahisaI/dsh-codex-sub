# 0.1.0-alpha.2 release notes

> Release candidate. This version has not been published, staged, or verified as public support.

## Candidate scope

This unpublished candidate updates the reviewed DSH compatibility line while retaining the
package-owned OAuth boundary and the pi-ai `0.82.1` integration. It must not be described as a
release-ready artifact or as public support.

## Candidate compatibility

- DeepSeek Harness `0.1.1-rc.1`
- DeepSeek Harness repository commit `528c682e061696f5a160f363f236ecbf53cbd006`
- `@deepseek-ai/cordis` `4.0.1`
- `@earendil-works/pi-ai` `0.82.1`
- Node.js `^22.19.0 || ^24.0.0 || ^26.0.0`
- Linux and macOS

The DSH release-family lock is pinned to exact `0.1.1-rc.1` identities, and the packed-install
topology gate requires two serving pi-ai `0.82.1` copies with no pi-ai override or resolution.
These are candidate checks only; publication and external release gates remain outstanding.

## Security boundary

Native DSH credential injection is fail-closed: reads are unset, writes/deletes/logout return fixed
safe errors, and environment/file lookup is empty. Package credentials are not migrated or copied
into the native store. The adapter owns a fixed 20 MiB image/base64 budget and replaces oversized
inputs with DSH-owned text before provider I/O.

The pi-ai `0.83.0` conclusion-B spike is retained as
[`compatibility evidence`](../compatibility-reports/pi-ai-0.83.0.md); it is not a supported
dependency or a candidate version.
